# Загрузка, медиа и жизненный цикл анимаций — 20 ноября 2026

Проверен опубликованный `875b227` на https://dumitru-spatial-portfolio.vercel.app/; рабочее дерево `5ae0bd5`. Runtime не менялся. Использованы новые изолированные контексты Chrome и WebKit, 390×844, DPR 3, touch. Это браузерная эмуляция, не физический iPhone. Нормальная анимация включена, reduced motion переключается отдельным шагом.

## Подтверждено работающим

- Холодный Home: **1 835 724 Б** ресурсов, 72 записи. Повторная загрузка того же контекста: **21 600 Б** передано. HTML не включён в resource total. Это лабораторный снимок нагрузки, не CWV реальных посетителей.
- Не загружаются скрытые обложки кейсов или MP4 на Home. Выбранное видео ANDRA отображает детализированный букет; снимки Chrome/WebKit сохранены. После ухода в About все плееры приостановлены.
- Home/About/Process останавливают SVG-планировщик; возврат Work снова запускает его. Исходный Home-персонаж не заменён.
- Включение reduced motion останавливает выбранное видео и активные часы движения. Переходы Work → ANDRA → About → Process → Work завершаются без зависания и ошибок JavaScript.
- Корневой документ не выходит за экран. Проверка медленной сети Chrome с latency 150 ms и throughput 200 000 B/s завершает загрузчик и открывает Home; готовые изображения декодированы. Эта эмуляция не воспроизводит все мобильные сети.
- Итог основной серии: Chrome **13/14**, WebKit **12/13**, ноль page errors. Единственный отрицательный assertion в каждом браузере относится к искусственному visibility-сценарию ниже; он не объявлен подтверждённым пользовательским багом.

Холодный handoff в последнем Chrome-прогоне: примерно 3,17 с от navigation start; cached handoff 2,83 с. Минимальные 2 с загрузчика и бумажное раскрытие заданы дизайном. Снимок сразу после `loader.phase=complete` может показывать разворачивающиеся полосы, а не окончательные изображения. Код `entry-flow.js:335–347` запускает раскрытие только после удаления loader, длительность 840 ms; `:397–400` задаёт предыдущий 600 ms уход loader. Поэтому первый пустой/частичный Home-кадр сам по себе не является дефектом.

## Кандидат для проверки на устройстве, пока не подтверждён

**Возобновление выбранного видео без дополнительного ввода после смены visibility.** В `probe.cjs` свойство `document.hidden` временно подменяется и отправляется `visibilitychange`. Видео корректно останавливается. После удаления подмены и события возвращения оно остаётся paused ещё 1,8 с, хотя `document.hasFocus()` true; одно движение указателя возобновляет его. Это одинаково наблюдается в Chrome и WebKit.

Важная граница: искусственное событие не полностью воспроизводит lifecycle браузера. Отдельный `visibility.cjs` попробовал настоящий переход между вкладками и CDP frozen/active. В этой headless-среде они **не перевели** document.hidden в true и не породили ожидаемую пару visibility-событий, поэтому такой запуск не подтверждает сбой после реального сворачивания телефона. Автоматическое исправление на основании одного synthetic теста не сделано.

Точки для дальнейшей диагностики: `site/_next/static/chunks/1l2px902fb04m.js:1` (native media visibility callback, byte ~10098; он явно делает pause при hidden), `site/_next/static/chunks/0n9xfy8bxft48.js:1` (idle/wake visibility handler, byte ~94500). Перед правкой проверить на реальном Safari: запустить выбранный ролик, переключить приложение/вкладку и вернуться без касания сайта. Не считать это доказанным iOS-багом и не добавлять новую кнопку паузы вопреки утверждённому интерфейсу.

## Метод и материалы

- `probe.cjs`: fresh/cached load, Home intent, выбранное видео, synthetic visibility, reduced motion, сцены и slow network.
- `visibility.cjs`: отдельная попытка browser-driven lifecycle; полные события и границы в `visibility-real.json`.
- Локально сохранены `chromium.json`, `webkit.json`, `*-video.png`, `slow-home.png`. Slow Home снят непосредственно при handoff и отражает промежуточный paper-unfold; не использовать как доказательство сломанных cutouts.
- Числа FPS, INP реальных пользователей, все возможные движения персонажа и длительные утечки памяти здесь не сертифицировались. Предыдущие исправления пустого WebKit-видео, фонового MP4 и остановки неактивного персонажа не регрессировали в проверенных обычных путях.

## Modern Web Guidance

Прочитаны `performance`, `motion`, `efficient-background-processing`. Для аудита использованы требования "DO provide a poster image fallback", "Keep the final state" и остановка ненужной фоновой работы. `content-visibility:auto` не навязывался фиксированной одноэкранной сцене; runtime и утверждённый дизайн не менялись.
